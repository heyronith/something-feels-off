# WO-004a: Fix WO-004 metrics keying bug and regenerate metrics (CPU)
Project: something-feels-off | Depends on: WO-004 (0b646ad) | Est. compute: 0 GPU-h (local or Modal CPU, < 15 min)

## Goal
Recompute every WO-004 metric correctly from the existing `results/WO-004/raw/` files. Do not run the model again.

## Context
- `scripts/wo_004_metrics.py` builds the lookup in `build_ld_maps` as `cell[set][class][cond][vec_key]` and **leaves out `prompt_idx`**.
  - Each vector's LD gets overwritten by the last prompt's row for that vector.
  - `matrix_for` then fills every prompt row with that single value.
  - So every derived metric is wrong (dLD, LD, p_LDneg, N, Rec, Eff, Suf, nonadd, hydra, lopo, compression fit).
  - Example: S1 concept steer dLD is reported as −19.62. A plain group-by over `raw/rows.jsonl` gives −15.18.
- The raw files are correct and must not be changed:
  - `raw/rows.jsonl` (39,646 rows)
  - `raw/controls.jsonl`
  - `raw/decomposition.jsonl`
  - `raw/dla_cache.pt` (on the volume or in a local pull)
- The metric definitions are those in `work_orders/WO-004.md` §6. Do not change them.

## Specification
1. **Fix the lookup.** Key every per-row lookup by **(set, class, cond, prompt_idx, vector_key)**. This covers LD, gate activations, rms_final, feat_act and anything else used by N^lin/Eff, the hydra check and the compression fit.
2. **Audit every per-row join.** Go through every function in `wo_004_metrics.py` that joins rows across conditions or to base, including N^lin, Eff, hydra, decomposition aggregation and the compression scatter. For each one, list in RUN_REPORT.md the key it uses after the fix.
3. **Regression test.** Add `tests/test_wo004_metrics.py` (CPU):
   - Use a tiny synthetic rows list with 2 prompts × 2 vectors whose values differ by prompt.
   - Assert that the per-condition mean dLD from `matrix_for` equals a plain pandas or numpy group-by.
   - This test must fail on the old code and pass on the fixed code. Show both outcomes in the RUN_REPORT.
4. **Real-data check.** Before writing metrics.json, compute with a plain group-by (independent of `matrix_for`) the mean LD and mean dLD per (set, class, cond) over `raw/rows.jsonl`. Assert that each equals the point estimate in the new metrics within 1e-6. Write the group-by table to `raw/groupby_check.csv`.
5. **Regenerate** `results/WO-004/metrics.json` and all `fig_*.png` with the fixed script. Keep the old file as `metrics_buggy_0b646ad.json` for the record.

## Sanity checks (a failed assert = stop and report; never loosen a threshold)
1. The regression test fails on the old code and passes on the fixed code.
2. The real-data check (step 4) passes for every (set, class, cond).
3. The counts are unchanged: 39,646 rows. Each (set, class, cond) cell has n = prompts × vectors (for example, S1 concept steer = 300).
